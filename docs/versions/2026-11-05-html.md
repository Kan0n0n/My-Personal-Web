# 1.2.0 — Ordinary HTML again

Date: 5 November 2026.

## Reason

The JavaScript-generated layouts made simple visual changes difficult to find. The owner requested a clean separation between normal HTML and behaviour.

## Changes

- Moved the complete header, navigation, sidebar, footer, and page-specific content directly into all nine main HTML files.
- Added editable shared HTML templates for repeated records, forms, empty states, reader controls, and weather panels in `templates/components.html`.
- Rewrote the main script with readable functions that clone templates, fill text/data attributes, and attach listeners. Neither browser script contains HTML strings or `innerHTML` assignment.
- Moved extractor loading/result/JSON/graph markup into templates in its own HTML page.
- Saving records now refreshes only data slots and lists, preserving manually added HTML, input bindings, and current audio playback.
- Kept browser storage keys and schemas compatible. HTML profile defaults remain distinct from saved profile overrides.
- Added an editing guide and updated architecture/function documentation and regression checks.

## Verification

The updated checks passed 31 local checks / 54 with HTTP checks. They cover static page/hook/template contracts, balanced HTML source tags, assets, safe text insertion, create/edit persistence, saved reloads, invalid URLs/backups, archive data, and HTTP routes/redirects/template loading. Syntax checks passed. These are source/logic checks with Element stubs, not a real browser engine.

Browser automation was unavailable for the prior redesign and interactive browser QA remains outstanding. Review actual desktop/phone layout, browser template parsing, native dialogs, audio, geolocation, and IndexedDB import/restore in a real browser. The missing extractor backend remains outside this update.
