# 1.2.1 — Music of the Day from a YouTube link

Date: 5 November 2026.

## Implementation

The home music widget accepts standard HTTP(S) YouTube watch links and youtu.be links. Clicking **Load music** extracts the video ID, requests metadata through the local server, validates the response, and updates the thumbnail, title, and channel name. **Listen on YouTube** opens the saved video in a new tab.

```text
YouTube link → bindAudio() → GET /api/music-info?videoId=…
→ YouTube oEmbed → displayMusic() → save() → applyProfile()
```

| File | Responsibility |
| --- | --- |
| `pages/index.html` | URL input, load button, artwork image, title/channel slots, and status text. |
| `assets/css/site.css` | 64px circular thumbnail with cover cropping and a border. |
| `assets/js/picturebook.js` | Link parsing, metadata request, display updates, and browser persistence. |
| `scripts/serve.mjs` | GET metadata endpoint, video-ID validation, upstream fetch, JSON/error responses. |

The endpoint accepts an 11-character video ID and returns `title`, `author_name`, and `thumbnail_url`. It rejects unsupported methods with 405, invalid IDs with 400, and upstream failures/timeouts with 502. The YouTube request has a ten-second timeout.

Profile fields `song`, `artist`, `musicCover`, and `musicUrl` are saved under the existing `philine-picturebook-v1` key. `musicUrl` is a canonical watch URL built from the validated ID. `applyProfile()` restores text, artwork, and listening link. Old notebooks receive empty cover/link defaults without changing the schema; the listening link stays hidden until a video is loaded again.

## Fixes included in this entry

- Centralised card updates in `applyProfile()`, removing the incomplete title selector and incorrectly quoted alternative text from `displayMusic()`.
- Validated title/channel/thumbnail and video ID before changing saved music, so incomplete responses leave the previous selection intact.
- Changed profile editing to merge form values with existing fields, preserving artwork and listening URL.
- Restored the original HTML artwork when a loaded notebook has no cover.
- Replaced inactive play/seek controls and removed unused local-audio globals. The widget now offers an actual YouTube listening link and accurate helper text.
- Surfaced server-provided error messages and distinguished a successful save from a storage failure. The load button always reenables.
- Updated stale file-picker checks and added persistence, profile-edit, input/error, and mocked API regression checks.

## Current limits and follow-up

- The result is a video thumbnail and uploader/channel name, not guaranteed album artwork or artist credit. The image URL needs network access; image bytes are not backed up.
- Playback opens YouTube in another tab; an embedded player, custom seek controls, and autoplay are not implemented.
- The Node metadata endpoint must run for new lookups; a static-only deployment does not provide it. Saved text can still restore independently of a new lookup.
